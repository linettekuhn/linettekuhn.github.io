Right away I recognized some similar concepts from JavaScript, but they look a little different with Kotlin. For example, the Elvis operator `(?:)` basically works like the ternary operator, which makes null-safety a lot cleaner. Classes in Kotlin automatically come with hidden getters and setters, and when it comes to variables, `var` makes them mutable while `val` locks them down as immutable (const). Inheritance also works differently; if you want a class or a function to be extended or overridden, you have to explicitly mark it with the `open` keyword. Another thing I noticed is how Kotlin treats functions as values. Instead of just passing the name, you need to use the function reference operator (`::`). And finally, trailing lambda functions are… interesting!

I also reviewed how the four core pillars of OOP translate into Kotlin:

- Encapsulation is handled through visibility modifiers, just like in other languages, using `public`, `private`, `protected`, and `internal` keywords.
- Polymorphism shows up when overriding functions and variables.
- Inheritance works with `extends` but again only if the parent class is marked `open`.
- Abstraction comes into play with interfaces, which let you define _what_ needs to be done without specifying down _how_ it’s implemented.

The second app is called Lemonade. In this simple app, the user clicks the image button to traverse through the stages of making a lemonade. The first screen is a lemon tree that, once clicked, takes you to the next screen with a lemon. In this second screen the user must click the lemon a random number of times to proceed to the next screen. In the third screen, the glass of lemonade can be clicked to “drink” it and move on to the fourth screen. Lastly, the user can click the empty glass to return back to the first screen and restart the process.

It might look simple, but this practice let me explore how to set up buttons and state variables, which basically make up the declarative UI design principle of Compose.
